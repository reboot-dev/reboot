Store remains upsert; actor admission, original generation, and uncertainty fences cannot be bypassed.

Python `TasksDispatcher.cancel_task` marks the original dispatched asyncio task cancelled, requests `task.cancel()`, and returns OK before its done-callback durably completes the cancellation terminal. Shutdown cancels asyncio tasks without setting that user-cancellation flag. Ordinary generated dispatch separately invokes the ordinary WorkflowStub (stable task-derived writer idempotency) and completes the task. The bounded Rust implementation deliberately waits for body quiescence and synchronous native terminal ACK before returning Cancel OK; this qualifies canonical cancellation/typed Wait behavior, not identical Python Cancel response timing or general middleware equivalence.

## Chosen capability

Canonical original-RPC admission of ordinary writer/reader tasks on explicitly registered existing actors using existing OneShotTasks and native atomic writer checkpoint authority. Plain DatabaseAdapter services use their existing generated typed binding and `_with_tasks` handler. Workflow-bearing adapters gain actual ordinary writer binding and dispatch through their existing `_scheduled` handler with the same local-state/task restrictions as unary execution. No fake engine/adapter substitutes or invented wire types.

Admission receipt/identity domains, workflow journal, duplicate-LAST metadata, immediate/absolute semantics and experimental target-clock relative workflow identities remain unchanged. Legacy experimental Spawn/SpawnAfter remain workflow-only. Generic capability is enabled only by canonical application RPC routing. Constructors, workflow-reader-wait descriptors and cursors remain fenced. TransactionAdapter database/transaction front doors explicitly reject task-schedule metadata before handler/participant work, rather than treating a spawn as an ordinary unary mutation; shared-factory methods remain unimplemented. This is a fail-closed boundary, not transaction task execution parity.

## Running ordinary task cancellation ownership

The ordinary dispatcher now owns a separate per-task interruption registration, retaining the original execution generation and channel identity. This is distinct from workflow post-CAS notification. After authorization and identity/authority checks, canonical Cancel publishes the pending-ACK fence and requests interruption before waiting for exclusive actor admission. The original execution drops/joins its own pending ordinary body under its existing lease; a caller never owns or replaces that body. Its signalled registration remains a handoff tombstone until the exact cancellation ACK (or restart on uncertainty), preventing a still-Pending canonical record from being redelivered through a replacement body while another cancellation owns CAS serialization. Readers relinquish shared admission only after dropping their future. Writers drop only before durable checkpoint work starts; once the sealed durable operation starts they retain the future and lease through its ACK or sticky failure. An acknowledged writer checkpoint can therefore survive a subsequent cancellation terminal.

State, saved ordinary response and successor tasks still commit atomically in Store. **Terminal task completion remains a separate CompleteTask CAS**, including cancellation. Actor admission proves body quiescence before cancellation CAS/ACK; it does not merge these two durable operations. No ordinary body runs after a winning Cancel ACK. Cancellation cannot preempt synchronous code or revoke remote effects already submitted.

The pending-ACK fence and uncertainty publication retain the existing original-owner mutex shared with Wait. Cancellation publishes an intent under the registration mutex even when no execution has registered yet, before waiting for terminal-CAS serialization. A late registration checks that exact generation and signalled intent under the same mutex and suppresses the body; an absent lookup cannot become an unsignalled reader parked ahead of exclusive cancellation admission. An authoritative NOT_FOUND lookup clears only its own acknowledged intent, while a dropped or uncertain request retains the suppression and owner fence until restart. Handoffs are counted independently, so concurrent Cancel requests can interrupt both shared reader bodies before terminal CAS serialization; serializing the handoffs themselves would deadlock two parked readers. The disclosure fence clears only after the last acknowledged handoff retires, with failure uncertainty published under that same mutex. Dropped requests, transport failure, lost ACK and changed generations cannot authorize catch-and-continue: task-owner uncertainty plus retained actor-gate commit uncertainty fence both terminal disclosure and concurrent ordinary writes until restart. Registration retirement checks channel identity so an old execution cannot erase a replacement.

## Explicit architecture limits

Qualification is scoped to explicitly registered local ordinary reader/writer targets and cooperative async bodies. Typed declared protobuf variants are task terminals; the unary-only `DeclaredStatus` rich-writer variant is still a framework failure in task dispatch (in particular, the existing one-detail task validator is not widened for multi-detail rich statuses). Handlers may rerun before their first acknowledged checkpoint; no exactly-once external side-effect guarantee is added. Synchronous execution cannot be preempted and already-submitted remote effects cannot be revoked. Dynamic placement/migration, Python-hosted UUID allocation, cursor receipt GC and transaction-adapter/task execution remain out of scope.
