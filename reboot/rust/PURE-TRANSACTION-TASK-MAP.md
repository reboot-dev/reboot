## Capability

A generated pure transaction adapter retains its existing constructor signature: participant, coordinator, start factory, handler. Its explicit `with_canonical_transaction_tasks(store, channel, application, bearer)` consumes a separately supplied task-journal store and validates the original participant's state type/reference, exact Database endpoint and prebound actor gate. The coordinator Database endpoint must also match. It does not bind or replace an actor gate implicitly. Register the returned adapter with the host only after attachment; task recovery must be host supervised before scheduling.

The pure binding has no ordinary reader/writer delegate or handler/store field. It validates only eligible exclusive non-factory transactions, invokes the generated public transaction RPC using the existing workflow journal capability, and rejects ordinary execution. It reuses the same transaction identity domain and original participant/coordinator; target commit or declared Abort/receipt, source journal and terminal CAS remain separate ACK boundaries. Existing authorization-before-replay and all uncertainty fences are unchanged.

Pure actor construction uses the existing exclusive factory path in separate bootstrap hosts before registered root-star task hosts start. The native driver constructs both actors through the actual pure generated Create RPC, gracefully joins each bootstrap host, and starts the task host against their retained native state. Registered trees retain their factory exclusion; no guard is relaxed. Exclusive factory transactions are not task targets. No shared factory task capability is introduced. Due/running cancellation remains rejected, future cancellation retains actor-gated synchronous CAS.
